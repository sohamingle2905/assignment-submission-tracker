# Assignment Submission Tracker

A simple college project for keeping track of assignments and their submission deadlines. Assignment records are stored in a local SQLite database and remain available after the server restarts.

## Technology stack

- Node.js 24 LTS
- Express.js
- EJS templates, HTML, and CSS for the server-rendered dashboard
- Vanilla JavaScript for the earlier frontend assets and reusable utilities
- SQLite with the `sqlite3` package
- Jest and Supertest for automated API tests
- GitHub Actions, GitHub, and Render (planned for later use)

## How to install

1. Install Node.js 24 LTS.
2. Open a terminal in the project folder.
3. Install the project dependencies:

   ```bash
   npm install
   ```

## How to run

Start the server:

```bash
npm start
```

The application automatically creates the `database` folder and `database/assignments.db` file and creates the assignments table when it starts. The database file is local and ignored by Git. Open [http://localhost:3000](http://localhost:3000) for the homepage or [http://localhost:3000/api/health](http://localhost:3000/api/health) for the health check.

The dashboard is rendered by Express with EJS templates. Add, edit, delete, and status-change actions use regular HTML forms, so these core features do not depend on browser JavaScript. The JSON API remains available under `/api/assignments`.

Run the automated backend tests with:

```bash
npm test
```

The Jest and Supertest suite checks assignment API responses, creation, validation, retrieval, updating, deletion, invalid IDs, and invalid status or priority values. Tests use a separate in-memory SQLite database, so they do not change records in `database/assignments.db`.

## SQLite database

The `assignments` table stores each assignment's ID, title, subject, description, due date, priority, status, and creation time. The API uses parameterized SQL (`?` placeholders) so request values are treated as data. The API maps the database's `due_date` column to the JSON field `dueDate`.

## Assignment API

All endpoints use and return JSON. Assignment IDs are generated by the database. A new assignment has this shape:

```json
{
  "id": 1,
  "title": "Database report",
  "subject": "Database Systems",
  "description": "Prepare the report",
  "dueDate": "2026-10-15",
  "priority": "Medium",
  "status": "Pending"
}
```

Valid priorities are `Low`, `Medium`, and `High`. Valid statuses are `Pending`, `In Progress`, and `Submitted`. The `title`, `subject`, `dueDate`, `priority`, and `status` fields are required. `dueDate` must use `YYYY-MM-DD`; `description` is optional and defaults to an empty string. `PUT` replaces all assignment details, so it also needs these required fields.

| Method | Endpoint | What it does | Success response |
| --- | --- | --- | --- |
| `GET` | `/api/assignments` | Lists all assignments. | `200 OK` with an array. |
| `GET` | `/api/assignments/:id` | Gets one assignment by ID. | `200 OK` with an assignment. |
| `POST` | `/api/assignments` | Creates an assignment from the JSON request body. | `201 Created` with the new assignment and a `Location` header. |
| `PUT` | `/api/assignments/:id` | Replaces an existing assignment's details using the JSON request body. | `200 OK` with the updated assignment. |
| `DELETE` | `/api/assignments/:id` | Deletes an assignment by ID. | `200 OK` with a confirmation and the deleted assignment. |

A successful `POST` request body example:

```json
{
  "title": "Database report",
  "subject": "Database Systems",
  "description": "Prepare the report",
  "dueDate": "2026-10-15",
  "priority": "Medium",
  "status": "Pending"
}
```

Invalid IDs and request data return `400 Bad Request` with a JSON error. A well-formed request for an assignment that does not exist returns `404 Not Found`. Database or unexpected server errors return `500 Internal Server Error`.
