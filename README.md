# Assignment Submission Tracker

A simple college project for keeping track of assignments and their submission deadlines. Assignment data is temporarily stored in memory and resets when the server restarts. SQLite is prepared as a project dependency for the next stage.

## Technology stack

- Node.js 24 LTS
- Express.js
- HTML, CSS, and vanilla JavaScript
- SQLite (planned for the next stage)
- Jest and Supertest (planned for later testing)
- GitHub Actions, GitHub, and Render (planned for later use)

## How to install

1. Install Node.js 24 LTS.
2. Open a terminal in the project folder.
3. Install the project dependencies:

   ```bash
   npm install
   ```

## How to run

Start the server:

```bash
npm start
```

Open [http://localhost:3000](http://localhost:3000) in your browser. The health check is available at [http://localhost:3000/api/health](http://localhost:3000/api/health).

## Assignment API

All endpoints use and return JSON. Assignment IDs are generated by the server. A new assignment has this shape:

```json
{
  "id": 1,
  "title": "Database report",
  "subject": "Database Systems",
  "description": "Prepare the report",
  "dueDate": "2026-10-15",
  "priority": "Medium",
  "status": "Pending"
}
```

Valid priorities are `Low`, `Medium`, and `High`. Valid statuses are `Pending`, `In Progress`, and `Submitted`. The `title`, `subject`, `dueDate`, `priority`, and `status` fields are required. `dueDate` must use `YYYY-MM-DD`; `description` is optional and defaults to an empty string. `PUT` replaces all assignment details, so it also needs these required fields.

| Method | Endpoint | What it does | Success response |
| --- | --- | --- | --- |
| `GET` | `/api/assignments` | Lists all assignments. | `200 OK` with an array. |
| `GET` | `/api/assignments/:id` | Gets one assignment by ID. | `200 OK` with an assignment. |
| `POST` | `/api/assignments` | Creates an assignment from the JSON request body. | `201 Created` with the new assignment and a `Location` header. |
| `PUT` | `/api/assignments/:id` | Replaces an existing assignment's details using the JSON request body. | `200 OK` with the updated assignment. |
| `DELETE` | `/api/assignments/:id` | Deletes an assignment by ID. | `200 OK` with a confirmation and the deleted assignment. |

A successful `POST` request body example:

```json
{
  "title": "Database report",
  "subject": "Database Systems",
  "description": "Prepare the report",
  "dueDate": "2026-10-15",
  "priority": "Medium",
  "status": "Pending"
}
```

Invalid IDs and request data return `400 Bad Request` with a JSON error. A well-formed request for an assignment that does not exist returns `404 Not Found`. Unexpected server errors return `500 Internal Server Error`.
